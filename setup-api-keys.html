🔐 API Key Setup - RobinsonLimitMP

⚠️ Security Notice: Never commit API keys to version control. This setup guide shows you how to keep your keys secure.

🌤️ Weather API Keys

The RobinsonLimitMP supports multiple weather APIs for reliable data. Here's how to set them up securely:

OpenWeatherMap (Primary)

The app primarily uses OpenWeatherMap for accurate weather data:

Step 1: Get Your API Key

  1. Go to OpenWeatherMap API
  2. Sign up for a free account
  3. Get your API key from the dashboard
  4. Note: New keys may take up to 2 hours to activate

Step 2: Configure Your API Key

Choose one of these secure methods:

Method A: Environment Variables (Recommended)

Create a .env file in your project root:

# .env file (DO NOT commit this file) OPENWEATHER_API_KEY=your_actual_api_key_here

Method B: Browser Configuration

Set the API key in your browser console (temporary):

window.OPENWEATHER_API_KEY = 'your_actual_api_key_here';

Method C: Direct Configuration

Update the config.js file (not recommended for production):

// In config.js, replace the fallback value: openWeatherMapApiKey: 'your_actual_api_key_here'

WeatherAPI.com (Optional)

For additional reliability, you can also add a WeatherAPI.com key:

  1. Go to WeatherAPI.com
  2. Sign up for a free account
  3. Get your API key from the dashboard
  4. Free tier includes 1 million calls per month

Configure it the same way as OpenWeatherMap:

# .env file WEATHERAPI_KEY=your_weatherapi_key_here # Or in config.js weatherApiKey: 'your_weatherapi_key_here'

🚀 Deployment Options

For GitHub Pages (Static Hosting)

Since GitHub Pages doesn't support environment variables, use one of these approaches:

  • Client-side only: Use wttr.in as primary weather source (no API key needed)
  • Server-side proxy: Create a simple backend service to proxy weather requests
  • Build-time injection: Use GitHub Actions to inject API keys during build

For Production Servers

Use environment variables on your server:

# Set environment variable export OPENWEATHER_API_KEY=your_api_key_here # Or in your deployment script OPENWEATHER_API_KEY=your_api_key_here npm start

For GitHub Pages with GitHub Actions (Recommended)

Use GitHub Actions to inject API keys during build time:

🚀 Quick Setup: This repository includes pre-configured GitHub Actions workflows. Just add your API key as a GitHub secret and you're ready to deploy!

Step 1: Add GitHub Secrets

  1. Go to your GitHub repository
  2. Click Settings → Secrets and variables → Actions
  3. Click New repository secret
  4. Add these secrets:
    • Name: OPENWEATHER_API_KEY
      Value: Your OpenWeatherMap API key
    • Name: WEATHERAPI_KEY
      Value: Your WeatherAPI.com API key (optional)
  5. Click Add secret for each

Step 2: Create GitHub Actions Workflow

Choose one of these workflow files:

Option A: Advanced Workflow (Recommended)

Creates a separate production config file. Copy .github/workflows/deploy.yml:

name: Deploy to GitHub Pages on: push: branches: [ main ] pull_request: branches: [ main ] jobs: build-and-deploy: runs-on: ubuntu-latest steps: - name: Checkout uses: actions/checkout@v4 - name: Setup Node.js uses: actions/setup-node@v4 with: node-version: '18' - name: Install dependencies (if any) run: | # Add any build steps here if needed echo "No dependencies to install for static site" - name: Inject API Key run: | # Create a temporary config file with the API key cat > config.prod.js << EOF // Production configuration with injected API key const config = { openWeatherMapApiKey: '${{ secrets.OPENWEATHER_API_KEY }}', weatherSettings: { primaryApi: 'openweathermap', fallbackApis: ['wttr', 'weatherapi'], timeout: 10000, retryAttempts: 2 } }; // Make it available globally if (typeof window !== 'undefined') { window.config = config; } // Export for Node.js if (typeof module !== 'undefined' && module.exports) { module.exports = config; } EOF - name: Update HTML to use production config run: | # Replace the config.js reference with config.prod.js sed -i 's/config\.js/config.prod.js/g' index.html - name: Deploy to GitHub Pages uses: peaceiris/actions-gh-pages@v3 if: github.ref == 'refs/heads/main' with: github_token: ${{ secrets.GITHUB_TOKEN }} publish_dir: .
Option B: Simple Workflow

Directly modifies config.js. Copy .github/workflows/deploy-simple.yml:

name: Deploy to GitHub Pages (Simple) on: push: branches: [ main ] jobs: build-and-deploy: runs-on: ubuntu-latest steps: - name: Checkout uses: actions/checkout@v4 - name: Setup Node.js uses: actions/setup-node@v4 with: node-version: '18' - name: Inject API Key into config.js run: | # Replace placeholder with actual API key sed -i "s/your_openweathermap_api_key_here/${{ secrets.OPENWEATHER_API_KEY }}/g" config.js - name: Deploy to GitHub Pages uses: peaceiris/actions-gh-pages@v3 with: github_token: ${{ secrets.GITHUB_TOKEN }} publish_dir: .

Step 3: Alternative - Environment Variable Injection

If you prefer to keep the original config.js, use this approach:

name: Deploy to GitHub Pages on: push: branches: [ main ] jobs: build-and-deploy: runs-on: ubuntu-latest steps: - name: Checkout uses: actions/checkout@v4 - name: Setup Node.js uses: actions/setup-node@v4 with: node-version: '18' - name: Inject API Key into config.js run: | # Replace placeholder with actual API key sed -i "s/your_openweathermap_api_key_here/${{ secrets.OPENWEATHER_API_KEY }}/g" config.js - name: Deploy to GitHub Pages uses: peaceiris/actions-gh-pages@v3 with: github_token: ${{ secrets.GITHUB_TOKEN }} publish_dir: .

Step 4: Enable GitHub Pages

  1. Go to repository Settings → Pages
  2. Source: Deploy from a branch
  3. Branch: gh-pages (created by the action)
  4. Folder: / (root)
  5. Click Save
⚠️ Security Note: The API key will be visible in the built files on GitHub Pages, but it's only accessible to users who inspect the page source. For higher security, consider using a server-side proxy instead.
